## 1. Established input invariant

By PO-5 and PO-6, every accepted trajectory reaches the Klein interface with exactly one Boolean value for every source variable.

Let `j_K` be the trajectory index of the Klein vertex `k`.

Then:

```text
alpha_pi(x_i) = beta_(j_K)(x_i)
```

defines a total Boolean assignment:

```text
alpha_pi : {x_1,...,x_n} -> {FALSE,TRUE}
```

The Active Relational Ledger proves assignment persistence:

```text
for all j >= j_K:
AssignmentView(Lambda_j) = alpha_pi
```

Therefore every clause gadget is evaluated against the same total assignment selected before K.

## 2. Clause gadget

For each source clause:

```text
C_j = (literal_j1 OR literal_j2 OR literal_j3)
```

the reduction constructs:

```text
              L_j1
             /    \
c_(j-1) --- L_j2 --- c_j
             \    /
              L_j3
```

with exactly these clause-local edges:

```text
c_(j-1) -> L_j1
c_(j-1) -> L_j2
c_(j-1) -> L_j3

L_j1 -> c_j
L_j2 -> c_j
L_j3 -> c_j
```

and no direct edge:

```text
c_(j-1) -> c_j
```

There are no edges between literal nodes of the same clause.

## 3. Fixed clause-validation semantics

For a literal node `L_jr`, let:

```text
Lit(L_jr)
```

denote its source literal.

The fixed rules S3 and S4 define:

```text
LiteralAdmissible(L_jr, Lambda_i)
iff
LiteralTrue(Lit(L_jr), AssignmentView(Lambda_i))
```

Specifically:

```text
Lit(L_jr) = x_h
=>
LiteralAdmissible(L_jr,Lambda_i)
iff beta_i(x_h) = TRUE
```

and:

```text
Lit(L_jr) = NOT x_h
=>
LiteralAdmissible(L_jr,Lambda_i)
iff beta_i(x_h) = FALSE
```

Because assignment state is invariant after K:

```text
LiteralAdmissible(L_jr,Lambda_i)
iff
alpha_pi satisfies Lit(L_jr)
```

for every clause-validation step.

# 6. Lemma 1: Clause-gadget cut property

**Lemma.** Every directed path from `c_(j-1)` to `c_j` traverses exactly one literal node:

```text
L_j1
L_j2
or
L_j3
```

### Proof

By construction, the only outgoing clause-region edges from `c_(j-1)` are:

```text
c_(j-1) -> L_j1
c_(j-1) -> L_j2
c_(j-1) -> L_j3
```

Each literal node has exactly one clause-forward edge:

```text
L_jr -> c_j
```

There is no direct edge:

```text
c_(j-1) -> c_j
```

and no edge between literal nodes.

Therefore a directed path crossing clause layer `j` must select one literal node and cannot select zero or more than one within that layer.

QED.

# 7. Lemma 2: Ordered traversal of all clause gadgets

**Lemma.** Every directed path from `c_0` to `t` traverses every clause gadget in order:

```text
C_1, C_2, ..., C_m
```

and traverses exactly one literal branch in each gadget.

### Proof

The clause-stage vertices form:

```text
c_0, c_1, ..., c_m
```

For each `j`, the only way to advance from `c_(j-1)` to `c_j` is through one of the three literal nodes by Lemma 1.

The construction contains no forward edge from `c_(j-1)` to any later clause stage:

```text
c_h
```

with:

```text
h > j.
```

The only clause-region edge into terminal `t` is:

```text
c_m -> t.
```

Therefore every directed `c_0`-to-`t` path traverses every clause layer exactly once and in index order.

QED.

# 8. Lemma 3: Global no-bypass topology

**Lemma.** Every directed `s`-to-`t` path in `G_phi` has the form:

```text
s
-> every variable gadget in order
-> a_n
-> k
-> c_0
-> every clause gadget in order
-> c_m
-> t
```

### Proof

The assignment-invariant proof established that every directed `s`-to-`k` path traverses every variable gadget in order.

By construction:

```text
a_n -> k
```

is the only edge from the assignment region into the Klein node, and:

```text
k -> c_0
```

is the only edge from the Klein node into the clause region.

By Lemma 2 every directed `c_0`-to-`t` path traverses every clause gadget.

No cross-layer edges are present in the construction.

Therefore no directed `s`-to-`t` path bypasses:

- a variable gadget;
- the Klein transition;
- a clause gadget.

QED.

# 10. Lemma 4: Satisfied literal iff literal branch is admissible

**Lemma.** During clause validation:

```text
LiteralAdmissible(L_jr,Lambda_i)
iff
alpha_pi satisfies Lit(L_jr).
```

### Proof

By PO-6, `alpha_pi` is a total Boolean assignment at K.

By assignment persistence, the assignment view after K is unchanged.

For a positive literal `x_h`, S3 accepts exactly when:

```text
beta_i(x_h) = TRUE.
```

This is equivalent to:

```text
alpha_pi(x_h) = TRUE.
```

For a negative literal `NOT x_h`, S4 accepts exactly when:

```text
beta_i(x_h) = FALSE,
```

equivalent to:

```text
alpha_pi(x_h) = FALSE.
```

Those are exactly the Boolean satisfaction conditions for the two literal forms.

QED.

# 16. Theorem PO-9: Terminal Equivalence

**Theorem.**

For an accepted structurally complete trajectory of the constructed instance:

```text
Recon(T_R,q_m)
iff
every source clause C_j has a selected literal
that is satisfied by alpha_pi.
```

### Forward direction

Assume:

```text
Recon(T_R,q_m).
```

Then every:

```text
c_j in T_R
```

is RECONCILED and has its required incorporated `ClauseWitness`.

By PO-7, reconciliation of each `c_j` implies that its selected literal is true under `alpha_pi`.

Therefore every source clause has a satisfied selected literal.

Hence:

```text
alpha_pi satisfies C_j
```

for every `j`.

### Reverse direction

Assume every source clause has a selected literal true under `alpha_pi`.

By PO-8, the trajectory traverses every clause gadget in order.

For each clause, Lemma 6 shows that the true selected literal makes the corresponding S5 transition admissible.

S5 sets:

```text
sigma_A(c_j) = RECONCILED
```

and incorporates the required `ClauseWitness`.

Therefore every target in:

```text
T_R
```

satisfies the Anchor reconciliation condition.

Thus:

```text
Recon(T_R,q_m).
```

Therefore:

```text
Recon(T_R,q_m)
iff
every source clause has a satisfied selected literal.
```

So:

```text
PO-9 Terminal Equivalence = PASS
```

QED.
